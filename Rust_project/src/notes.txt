1. RUST ERROR INDEX
================================================================================

Rust gives every compiler error a unique identifier (e.g., E0277, E0308).
You can look up detailed explanations for any error directly from the terminal:

    rustc --explain E0277

This outputs a full explanation with:
  - What the error means
  - Why it occurs
  - An example of erroneous code
  - How to fix it

Example Error — E0277 (Trait Not Implemented):

    // Declare a trait with a required method
    trait Foo {
        fn bar(&self);
    }

    // This function requires `T` to implement `Foo`
    fn some_func<T: Foo>(foo: T) {
        foo.bar();
    }

    // Calling `some_func(42)` would trigger E0277 because
    // `i32` does not implement the `Foo` trait.

Tip: Always read the error message carefully — Rust's compiler messages are
considered some of the best in any programming language.

See: variable_shadowing.rs, scope.rs, etc. for working examples.


2. VARIABLE SHADOWING
================================================================================

Shadowing allows you to redeclare a variable with the same name using `let`.
The new declaration "shadows" (hides) the previous one.

Syntax:
    let x = "hello";   // x is &str
    let x = 5;         // x is now i32 — the string version no longer exists

Key Differences from Mutation (`mut`):
┌─────────────────────────┬──────────────────────┬─────────────────────────┐
│ Feature                 │ Shadowing (`let`)    │ Mutation (`mut`)        │
├─────────────────────────┼──────────────────────┼─────────────────────────┤
│ Can change type?        │ ✅ Yes               │ ❌ No                   │
│ Creates new variable?   │ ✅ Yes               │ ❌ No (same binding)    │
│ Keyword needed?         │ `let` again          │ `let mut` at first      │
│ Old value accessible?   │ ❌ No (overwritten)   │ ❌ No (replaced)        │
└─────────────────────────┴──────────────────────┴─────────────────────────┘

Example:
    let grams_of_protein = "100.345";   // type: &str (string slice)
    let grams_of_protein = 100.345;     // type: f64  (floating-point)
    let grams_of_protein = 80;          // type: i32  (integer)

Each `let` creates a completely NEW variable. The type is determined by the
value in the latest binding — previous versions become invalid.

See: variable_shadowing.rs


3. SCOPE
================================================================================

A **scope** is a region of code enclosed in curly braces `{ }` where variable
bindings are valid.

Rules:
  1. A variable is accessible from its declaration to the end of its `{ }` block.
  2. Inner (nested) scopes CAN access variables from outer scopes.
  3. If an inner scope shadows a variable, the outer value is RESTORED when
     the inner scope ends.
  4. Variables are automatically DROPPED (destroyed) at the end of their scope.

Example:
    {
        let coffee = 6.75;
        println!("{coffee}");           // ✅ Prints: 6.75

        {
            let coffee = 5.0;          // Shadows outer `coffee`
            println!("{coffee}");       // ✅ Prints: 5.0
        }                               // Inner `coffee` is dropped here

        println!("{coffee}");           // ✅ Prints: 6.75 (outer restored!)
    }
    // println!("{coffee}");            // ❌ ERROR: `coffee` is out of scope

Why this matters:
  - Rust uses scope to manage memory — no garbage collector needed.
  - When a variable goes out of scope, Rust automatically frees its memory.
  - This is part of Rust's "ownership" system (covered in later topics).

See: scope.rs


4. CONSTANTS
================================================================================

A **constant** (`const`) is a value that is fixed at COMPILE TIME and can
never change during the program's execution.

Syntax:
    const NAME: Type = value;
    const TAX_RATE: f64 = 0.075;

Constants vs Immutable Variables (`let`):
┌──────────────────────────┬────────────────────────┬──────────────────────────┐
│ Feature                  │ `const`                │ `let` (immutable)        │
├──────────────────────────┼────────────────────────┼──────────────────────────┤
│ Scope                    │ Any scope (global!)    │ Only inside its block    │
│ Type annotation          │ Required               │ Optional (type inferred) │
│ Value determined at      │ Compile time           │ Runtime                  │
│ Can be shadowed?         │ ❌ No                   │ ✅ Yes                   │
│ Naming convention        │ SCREAMING_SNAKE_CASE   │ snake_case               │
│ Can use in expressions?  │ ✅ Yes (inlined)        │ ✅ Yes                   │
└──────────────────────────┴────────────────────────┴──────────────────────────┘

Example:
    const TAX_RATE: f64 = 0.075;        // Declared OUTSIDE fn main()

    fn main() {
        let income: f64 = 755_000.0;    // Underscores improve readability
        let income_tax = income * TAX_RATE;
        let income_after_tax = income - income_tax;

        println!("Salary Yearly:       {}", income);
        println!("Tax Rate:            {}", TAX_RATE);
        println!("Income Tax:          {}", income_tax);
        println!("Take-Home After Tax: {}", income_after_tax);
    }

Common use cases for constants:
  - Mathematical values:  const PI: f64 = 3.14159265;
  - Configuration:        const MAX_RETRIES: u32 = 5;
  - Rates/thresholds:     const TAX_RATE: f64 = 0.075;

See: constants.rs


5. TYPE ALIASES
================================================================================

A **type alias** creates an alternative name for an existing type using `type`.

Syntax:
    type AliasName = ExistingType;
    type Meters = i32;

Why use type aliases?
  1. **Readability** — `Meters` is clearer than a bare `i32` for distances.
  2. **Consistency** — Change the underlying type in one place, all usages follow.
  3. **Domain modelling** — Gives semantic meaning to primitive types.

Important caveat:
  A type alias does NOT create a new, distinct type. `Meters` and `i32` are
  fully interchangeable — the compiler treats them as identical. You can still
  accidentally mix up `Meters` and `Seconds` if both alias to `i32`.

Example:
    type Meters = i32;

    fn main() {
        let mile_race_length: Meters = 1600;
        let two_mile_race_length = mile_race_length * 2;

        println!("1-mile race: {} meters", mile_race_length);
        println!("2-mile race: {} meters", two_mile_race_length);
    }

See: type_aliases.rs


6. COMPILER DIRECTIVES (ATTRIBUTES)
================================================================================

A **compiler directive** (officially called an **attribute** in Rust) is an
annotation that tells the compiler how to handle specific pieces of code.

Syntax:
    #[attribute]      — Applies to the NEXT item (function, struct, etc.)
    #![attribute]     — Applies to the ENTIRE enclosing item (file/crate)

Common Attributes:
┌─────────────────────────────────┬──────────────────────────────────────────────┐
│ Attribute                       │ Purpose                                      │
├─────────────────────────────────┼──────────────────────────────────────────────┤
│ #[allow(unused_variables)]      │ Suppress "unused variable" warning           │
│ #![allow(unused_variables)]     │ Suppress for the entire file                 │
│ #[allow(dead_code)]             │ Suppress "function never used" warning       │
│ #[derive(Debug)]                │ Auto-generate Debug trait implementation     │
│ #[derive(Clone, PartialEq)]    │ Auto-generate Clone and PartialEq traits     │
│ #[cfg(test)]                    │ Compile this block only during `cargo test`  │
│ #[test]                         │ Mark a function as a unit test               │
└─────────────────────────────────┴──────────────────────────────────────────────┘

Example:
    #![allow(unused_variables)]   // Applied to the whole file

    #[allow(unused_variables)]    // Applied only to the next function
    fn main() {
        let unused_var = 42;      // No warning!
    }

See: compiler_directives.rs
